# 잡몹 AI 공격 정리 (c2540 · c2550 · c2560)

대상 폴더: `data/gamefiles/ai/`. 인용은 `파일:줄`. 줄임말: Sword = `HusiFight_Sword254000Battle.lua`, Ax = `HusiFight_Ax254001Battle.lua`,
FireBom = `HusiFight_FireBom254002Battle.lua`, Long = `HusiHeavy_Long255001Battle.lua`, Spear = `HusiHeavy_Spear255000Battle.lua`,
LKSword = `LightKnight_Sword256000Battle.lua`, Rapier = `LightKnight_Rapier256002Battle.lua`, cbf = `common_battle_func.lua.lua`, cf2 = `common_func2.lua.lua`.

읽은 것은 "어떤 goal을 어떤 순서로 큐에 넣는가"까지다. `Attack` / `ComboAttack` / `ComboRepeat` / `ComboFinal` / `NonspinningAttack` /
`AttackTunableSpin` / `ComboAttackTunableSpin` / `SpinStep` 본체는 Lua에 없다 (엔진 쪽, 번호만 `goal_list.lua.lua:317-348`).
그래서 큐에 넣은 뒤 실제로 몇 타가 나가는지, 언제 끊기는지는 이 문서로 알 수 없다.

## 0. 공통 구조

- 선택: Activate가 거리별 가중치 `actPerArr[n]`을 채우고 `Common_Battle_Activate`가 1..합계 난수로 Act 하나를 고른다 (cbf:174-185). 확률 = 가중치/합계.
- 스크립트가 `actFuncArr[n]`을 안 채운 칸은 기본 `defActNN`이 `defFuncParamTbl[n]` 값으로 돈다 (cbf:140-145):
  defAct01/03 = 접근 후 공격 1회 `Approach_and_Attack_Act` (cbf:195-240) · defAct02 = 3000 계열 콤보 (cbf:210-225, 503-524) ·
  defAct04 = 접근 → `GuardBreakAttack` → `ComboFinal` (cbf:242-257, cf2:598-613) · defAct08 = `Watching_Parry_Chance_Act` (cbf:291-299).
- 공격 뒤 간격 조정: Act가 돌려준 값(%) 확률로 `GetWellSpace_Act_IncludeSidestep` 실행 (cbf:188-191, cf2:639-668).
  인자 = {이동 중 가드%, 그대로, 뒤+옆걸음, 뒤로, 잠깐 대기, 백스텝 701, 옆스텝 702/703 반반}.
- `Approach_Act`: AppDist까지 접근, AppDist+2 이상 떨어져 있으면 달림, Odds_Guard% 확률로 가드(9910) 들고 (cf2:689-705).

### 회전 관련 goal (Lua에서 보이는 것만)

| `AttackTunableSpin` | `Approach_and_Attack_Act`가 넣음 (cf2:578) | turnTime 기본 1.5 s, turnFaceAngle 기본 20° (cf2:575-576) |

- 인자 이름 근거: 같은 구조의 `GuardBreakTunable` 디버그 이름이 3번 "공격 전 선회 시간(초)", 4번 "정면 판정 각도(도)"이고 음수면 1.5 s / 20°로

### 플레이어 위치(뒤·옆) 분기 — 전체 결론

- 7개 전투 스크립트에 `IsInsideTarget`, `TurnAround`, `SpecialTurn` 호출이 없다 (grep). `AI_DIR_TYPE_*`는 SpinStep 방향으로만 쓰인다
  (B=701 백스텝, L=702, R=703; ai_define.lua.lua:6-8).
- 즉 "플레이어가 뒤/옆이면 다른 공격" 분기는 없다. 방향은 (1) 공격 전 `ApproachTarget`, (2) `AttackTunableSpin` 선회
  (정면 20° 안에 들 때까지 최대 1.5 s로 읽힘), (3) 엔진 쪽 Attack goal 기본 동작에 맡긴다.
- 예외는 Rapier: 패리는 플레이어가 정면 60° 안일 때만 (cf2:739, 744), 백스탭은 "등 뒤 관찰 영역" 진입 때 (3-2절).

### 공통 인터럽트 (플레이어 행동에 반응)

- `FindAttack_Step_or_Guard`(플레이어 공격 시작) / `Damaged_Step_or_Guard`(피격): 거리·확률 통과 시 step% → SpinStep 뒤/좌/우, 나머지 → LeaveTarget (+50% SidewayMove) (cf2:175-210, 267-302).
  `FindAttack_Step` / `Damaged_Step`은 스텝만 (cf2:131-152, 244-265).
- `MissSwing_Int`(플레이어 헛스윙) · `SuccessGuard_Act`(적이 막음) · `GuardBreak_Act`(플레이어 가드 깨짐) · `UseItem_Act`(플레이어 아이템): 서브골을 비우고 true → 스크립트가 반격을 넣음 (cf2:304-359, 444-454).
- `Shoot_2dist`(플레이어 사격): 가까움=1, 멂=2 (cf2:376-396). `RebByOpGuard_Step`(적 공격이 방패에 튕김): SpinStep 뒤/좌/우 (cf2:421-442).

# bot/ — 에피소드 학습 봇 (작업 중)

스트리머용 어댑터(상위 폴더)와 별개로, **엘든링을 자율 순찰하고 실패에서 배우는 봇**을 만드는 곳입니다.
목표와 단계는 [docs/DEVELOPMENT.md](../docs/DEVELOPMENT.md) 의 "에피소드 학습" 항목 참고.

## 1단계 (완료): 텔레메트리 + Recorder

```
Cheat Engine 브릿지 ── symbols.json ──▶ telemetry.py (pymem, 읽기 전용) ──▶ record.py (JSONL 에피소드)
```

- `telemetry.py` — 플레이어·주변 캐릭터(537개 중 반경 내) 상태를 초당 수십 회 읽음. 포인터 경로는 Hexinton 8.0.4 테이블에서 가져옴
- `record.py` — 10Hz 로 에피소드 파일 기록. 사망 시 직전 30초를 `.death.json` 으로 따로 저장 (복기 재료)

### 실행

```bash
# 게임 오프라인 실행 → 캐릭터 로드 → (상위 폴더에서) npm run attach   ← symbols.json 을 내보냄
cd bot
.venv\Scripts\python.exe telemetry.py      # 실시간 표시
.venv\Scripts\python.exe record.py         # 기록 시작 (Ctrl+C 로 종료)
```

venv 만들기 (처음 한 번): `uv venv .venv --python 3.12 && uv pip install --python .venv/Scripts/python.exe pymem python-dotenv`

## 2단계 (완료): 순찰 봇

```
telemetry (좌표·카메라 yaw) ──▶ nav.goto (조향 루프 20Hz, 막힘 탈출) ──▶ control.Pad (ViGEmBus 가상 Xbox 패드)
                                     ▲
                              patrol.py (웨이포인트 A→B→A, Guard, 에피소드 기록)
```

- `control.py` — vgamepad 래퍼. 실측: 왼스틱 앞 = 카메라 yaw 방향, 오른쪽 = +90°, 걷기 2.5 m/s / 달리기 3.7 m/s
- `nav.py` — `goto((x, z))`: 카메라 기준 조향, 2초간 0.3 m 미만 진행이면 점프+옆걸음 탈출
- `patrol.py record <이름>` — 실제 패드로 걸으면 4 m 마다 웨이포인트 저장
- `patrol.py run <이름> --laps N` — 왕복 순찰 + Guard(피격 시 구르기, HP<50% 성배병, HP<35% 후퇴, 적 3+ 스프린트) + 에피소드 기록

실측(2026-09-21): 최초의 계단 → 다음 축복 204 m 경로(42 지점)를 **혼자 왕복 완주** (82 지점 도착, 사망 0, Guard 구르기 1회).

### 캐릭터 상태 규칙 (2026-09-21 추가)
- **양손 잡기**: 이 캐릭터는 왼손이 비어 있어서 오른손 무기를 **양손으로** 잡은 상태(`[[GameDataMan]+8]+0x324` ArmStyle = 3)에서만 LB 가 가드다.
  한손(1)이면 LB 는 주먹이라 `guardjump` 가 "주먹질+점프" 가 된다. 에피소드 시작 때 `ensure_two_hand` 가 Y홀드+RB 로 맞추고,
  도중에 풀리면(사람이 바꿀 수 있다) Guard 가 가드 모드를 끄고 적이 10 m 밖일 때 다시 양손으로. 에피소드 파일에 `"event": "armstyle"` 로 남는다.
- **서 있지 않는다**: 이 게임은 길 위에 멈춘 캐릭터를 용납하지 않는다 — 쉬는 건 축복에서. 살아 있는데 4 s 동안 0.5 m 도 못 움직이면
  입력이 안 먹는 것(포커스 상실·팝업·패드 재인식)으로 보고 포커스를 다시 잡고 B 를 누른다(팝업이면 닫기, 게임이면 구르기).
  3번 흔들어도 그대로면(또는 웨이포인트 3개 연속 실패) 에피소드를 `stall` 로 끝내고 축복으로 돌아간다 — `stall` 은 생존 집계에서 뺀다.
  후퇴도 도착해서 2 s 서 있던 것을 없애고 조건이 남아 있으면 계속 뒤로 간다(최대 3 지점). 런이 끝나면 캐릭터를 축복으로 돌려보낸다.
- **성배병**: HP 가 `flask_hp_pct`(50%) 아래면 마신다. 적이 4 m 안이면 마시다 맞으니 먼저 후퇴해서 거리를 벌리고 마신다.
  남은 수는 인벤토리 배열(`[[[GameDataMan]+8]+0x418]`, goods 1000~1012)에서 읽는다 (`telemetry.flasks()`), 최대는 `+0x101`.
- **1병 남으면 무조건 휴식**: `REST_FLASKS_LEFT`(1) 이하면 순찰을 끊고 축복(`route.grace_pos`)으로 가서 Y 로 앉는다 →
  HP·성배병 충전 확인 → B 로 일어나 가장 가까운 웨이포인트부터 순찰 재개. 에피소드 파일에 `"event": "rest"`.
  실측: 앉기 판정 반경이 0.7 m 미만이라 `grace_pos` 는 격자 탐색으로 찾은 정확한 지점(워프 도착점에서 1.5 m)이고, 0.35 m 오차로 밟는다.
  브릿지 `warp` 는 위치만 옮기고 성배병을 채우지 않는다 (리셋이 채우는 건 리스폰 덕). 앉으면 anim 68011.
  (지금은 경로 시작 축복 하나만 안다 — 반대편 끝 축복의 ID/위치를 `graces` 로 넣으면 더 가까운 쪽을 고르게 확장.)
  (실측: 오전 런 하나는 입력이 씹혀 131 s 를 서 있었는데 "150 s 생존" 으로 기록돼 있었다 — 이런 게 학습을 망친다.)

### 좌표 주의
`ChrIns+0x6C0` 의 좌표는 **256 m 타일 기준 상대값**이라 타일 경계에서 124 → -128 로 튄다.
`telemetry.tile_to_world()` 가 MapID(0xAAXXZZ00)의 타일 번호 × 256 을 더해 연속 좌표로 만든다. 경로·순찰은 전부 이 연속 좌표를 쓴다.

### 필요한 것
- **ViGEmBus 드라이버** (`winget install --id ViGEm.ViGEmBus -e`) — 가상 패드
- 게임 창이 포그라운드여야 패드 입력이 먹음. CE 의 Lua Engine 창이 뜨면 포커스를 뺏으므로 브릿지가 CE 의 `print` 를 파일 로그로 돌려 놓음

## 3단계 (완료): 플레이북 + 복기 + 롤백 (에피소드 학습)

```
learn.py ─▶ reset_episode(즉사→리스폰→시작 축복 워프) ─▶ run_episode(순찰 + Harasser 방해 소환)
        ─▶ 사망이면 postmortem.diagnose → propose(R1~R5) ─▶ 같은 제안 2회 누적 시 playbook.apply → v+1
        ─▶ 새 버전으로 3 에피소드 뛴 뒤 생존 중앙값 < 이전×0.8 이면 롤백 + rejected 기록
```

- `playbook.py` — 버전 관리되는 파라미터 묶음 (후퇴/성배병 HP%, 군집 임계, 회피 타입, 이동 모드, 스태미나 걷기%). 범위 밖 제안은 `apply` 가 거부
- `harass.py` — 어댑터의 소환 효과를 "시청자 방해 시뮬레이터"로 주기 소환 (시드 고정, 에피소드마다 다름)
- `postmortem.py` — 사망 30초 전 기록에서 killers / 첫 피격 HP / 적 수 / 구간 / 성배병·후퇴 여부 → 규칙 R1(회피 타입) → R2(군집↓) → R3(성배병↑) → R4(후퇴↑) → R5(구간 스프린트)
- 이동 모드: 적 없음 `sprint`, 적 20 m 안 `guardjump`(가드 유지 + 1.2 s 마다 점프 — 빠르고 점프 무적·가드 보호), 스태미나 25% 아래 `walk`

```
python learn.py limgrave-1 --episodes 10 --max-seconds 150 --harass-interval 15
```
실측: 자동 롤백 동작 확인 (v2 "Warhawk 회피" 중앙값 68 s < v1 93 s×0.8 → v3 롤백).

## Jev (TypeSafe AI System One) — 선택, 실험 중

Jev 는 문장을 생성하지 않고 **정해진 선택지(choice)·점수(score)·확률(noul)** 로만 답하는 판단 모델이다 (≈0.1 s, 입력 10억 토큰당 $42).
텍스트 LLM 을 틱 루프에 넣는 대신, 이벤트가 있을 때만 "지금 이동 모드는? 후퇴해야 하나? 위협 수준은?" 을 묻는다.

| 자리 | 함수 | 트리거 | Jev 가 못 건드리는 것 |
|---|---|---|---|
| 구간 정책 | `jev.decide_move` | 적 수 변화 · 피격 · 적 있는 채 3 s | 구르기·성배병·스태미나 걷기 (항상 규칙) |
| 복기 랭킹 | `jev.rank_proposals` | 사망 복기 | 후보는 규칙 R1~R5 가 만든 것만, 범위는 `playbook.apply` |

규율: `confidence < JEV_MIN_CONF(0.6)` 이면 규칙을 따름 · 실패/타임아웃/일일 상한이면 즉시 규칙 폴백 · 모든 호출은 `data/jev.jsonl` 과 에피소드 행(`"jev"`)에 기록.

```
python learn.py limgrave-1 --episodes 10 --jev shadow   # 복기 후보 선택을 기록만 (규칙이 적용)
python learn.py limgrave-1 --episodes 10 --jev live     # 판단 모델의 복기 선택을 적용 (게이트 미달·NONE 이면 규칙)
#   --jev-tick 을 붙이면 틱 단위 이동모드·후퇴 질문도 켜짐 (shadow: 기록, live: 따름) — 실측상 무의미해 기본 꺼짐
python jev_report.py                                    # off/shadow/live 생존 중앙값, 규칙 일치율, 사망 전 조기경보율

# A/B: 같은 시작 플레이북·같은 시드열, 팔마다 data/playbook/arms/<이름>/ 에 버전·성적 분리
python learn.py limgrave-1 --episodes 10 --max-seconds 150 --harass-interval 15 --seeds-fixed --arm jev   --jev live
python learn.py limgrave-1 --episodes 10 --max-seconds 150 --harass-interval 15 --seeds-fixed --arm rules --jev off
python ab_report.py jev rules                           # 생존초 나열, 전반→후반 중앙값, 버전별, 변경 이력, 순열검정 p
```
채택 기준: `live` 의 생존 중앙값이 규칙만일 때보다 높아야 한다. 아니면 끈다.

백엔드 (`.env`): `AI_GATEWAY_API_KEY` (Vercel AI Gateway 경유 Jev, 무료 크레딧 월 $5, 카드 등록만 필요·충전 금지) 또는 `TYPESAFE_API_KEY`(직접) → `typesafe`;
둘 다 없으면 `JEV_BACKEND=local` 로 LM Studio/Ollama 의 OpenAI 호환 서버(`LOCAL_LLM_URL`, `LOCAL_LLM_MODEL`) — 같은 질문을 JSON 스키마로 강제.

실측 (2026-09-21, 같은 조건 그림자 런 — `python jev_compare.py`):

| | 로컬 Qwen3-4B (LM Studio, RTX 5080) | Jev (Vercel 게이트웨이) |
|---|---|---|
| 지연 | 중앙값 1.0 s (localhost→127.0.0.1 로 2 s 절감 후) | **0.34 s**, 최대 0.9 s |
| 확률·신뢰도 | 항상 0.95 / logprob 는 1.0·0.0 (정보 없음) | 진짜 분포. 22% 는 스스로 "확신 없음" → 규칙에 양보 |
| 이동 모드 | 100% guardjump | 97% guardjump — **둘 다 틱 단위 판단으론 가치 없음** |
| 5 s 안 피격 여부 구분 (threat) | 2.08 vs 1.98 | 2.52 vs 2.21 — 둘 다 약함, 오경보 70~80% |
| 복기 후보 선택 | 과신 (conf 0.8~1.0), 규칙보다 나쁜 선택 1/3 | 규칙과 다른 선택 2/5 ("첫 피격 때 이미 HP 낮음 → 더 일찍 후퇴"), 게이트 미달 2/5 |
| 비용 | GPU 2.3 GB | 159회 124k 토큰 = $0.005 (무료 크레딧) |

결론: 판단 모델은 **복기(A)** 에만 쓴다. 틱 단위 이동 모드(B)는 둘 다 규칙과 다를 바 없어 끈다. 그림자 런의 생존 차이는 판단 모델이 아니라 플레이북 버전·시드 차이다 — 판단 모델의 가치는 `--jev live` 로 10 에피소드 이상 돌려 규칙만일 때와 생존 추세를 비교해야 나온다.

### A/B 실측 (2026-09-21 12:27–13:11, 같은 v7 시작, 시드 1000–1009 동일, 150 s 상한, 방해 15 s) — `python ab_report.py jev rules`

| | jev (Jev 가 복기 후보 선택, 게이트 0.25) | rules (규칙 R0~R5 첫 후보) |
|---|---|---|
| 생존초 (시드 순) | 150 46 126 33 46 · 150 32 150 42 150 | 150 44 71 30 150 · 134 33 150 117 150 |
| 중앙값 / 사망 | 86 s / 7 | **126 s** / 6 |
| 전반→후반 중앙값 | 46 → 150 | 71 → 134 |
| 변경 | ep5 v8 crowd_threshold 3→2 (Jev), ep8 v9 Dog 회피 철회 (규칙, Jev 게이트 미달) | ep3 v8 Warhawk 회피 철회, ep7 v9 Dog 회피 철회 |
| 차이 | −39 s, 순열검정 p = 0.68 (n=10 이면 당연히 유의하지 않음) | |

읽는 법:
- **같은 시드에서 갈린 곳**은 1004(46 vs 150)와 1008(42 vs 117) — 둘 다 jev 팔이 Warhawk 에게 죽은 자리. rules 팔은 ep3 에 "Warhawk 를 피해 도망쳐도 죽는다 → 회피 철회"(R0)를 적용했고 그게 맞았다. jev 팔에선 Jev 가 매번 R0 대신 "구간 스프린트"·"군집 임계↓" 를 골라(conf 0.29·0.46·0.46) R0 의 근거가 2회에 못 미쳤다. **Jev 는 "날아다니는 적에게서 도망치면 죽는다" 는 게임 지식이 없다** — 그건 규칙(우리)이 넣은 것.
- 게이트 0.6 이면 Jev 는 4/4 기권해서 팔이 규칙과 같아진다 (`arms/_aborted-jev-gate0.6`). 0.25 로 내려서야 4/8 에서 골랐다. 3~4지선다에서 conf 0.6 은 거의 안 나온다.
- 같은 v7·같은 시드 1002 에서 126 s vs 71 s — **동일 설정의 잡음이 55 s**. 이게 바닥이라 n=10 의 중앙값 차이 39 s 는 의미 없다.
- 그래도 두 팔 다 후반이 전반보다 길다 (46→150, 71→134). "죽고 → 복기 → 고치고 → 더 산다" 루프 자체는 돈다. 단, 회피 철회 두 번(R0)이 한 일이고 판단 모델이 한 일은 아니다.

결론(현재): 복기 후보 선택도 규칙이 낫다. Jev 를 다시 쓰려면 (1) 규칙이 이미 아는 것(R0 같은 도메인 지식)을 후보 설명에 넣어 주거나, (2) 후보를 규칙 순위대로 두고 Jev 는 "규칙 1순위를 뒤집을 만큼 확신할 때만" 개입하게 하는 게 맞다. 팔당 30 에피소드는 쌓아야 어느 쪽이든 말할 수 있다.

### 답 줄 채점(S3) 판단기 — 사전 등록 탈락 (2026-09-22, `score_judge.py`)
모델이 적는 신뢰도 대신 **후보 줄 전체의 로그우도**로 고르고 1·2등 차(마진)를 신뢰도로 쓰는 방식 (VersionSandbox `docs/escalation_gate_probe.md` 의 S3).
LM Studio 의 logprobs 는 샘플링 뒤 분포라 못 쓰므로 `llama-cpp-python` 0.3.19 를 **Vulkan** 으로 빌드했다 (별도 venv `.venv-llm`, VS2019 BuildTools + Vulkan SDK, 3분 47초).
Qwen3-4B Q4_K_M, 상인 달리기 전술 4개, 사전 등록한 상황 12개(기대 답 10 + 모호 2).

| 판정선 (실행 전 고정) | 결과 |
|---|---|
| (1) 기대 답 일치 ≥ 8/10 | **3/10 — 탈락.** 12개 전부 `bomb_stop`, 마진 7~16 nats (적이 없는 상황에서도 확률 1.00) |
| (2) 모호한 상황의 마진 < 일치한 상황의 마진 | 12.4 < 13.5 (통과처럼 보이지만 (1) 이 무너져 의미 없음) |
| (3) 호출당 p50 < 300 ms | **122 ms** (p90 142, 후보 4개, 시스템 부분 KV 캐시). 단 게임을 끈 채 — 켠 채는 미측정. 같은 질문의 LM Studio JSON 선택은 184 ms, 역시 12/12 `bomb_stop` |

진단 (판정은 그대로, 원인만): 시스템 프롬프트의 "폭탄 선호" 원칙 문장을 빼면 세 상황 모두 `fight` 로 **통째로** 바뀌고, 후보 순서를 뒤집으면 답은 그대로에 마진만 흔들리고,
이름을 a/b/c/d 로 가려도 `bomb_stop` 의 설명을 고른다 → **4B 모델은 상태(STATE)를 거의 읽지 않고 프롬프트 문구로 답한다.** 엘든링에서 이동 모드가 100 % guardjump 였던 것과 같은 현상.
VersionSandbox 에서 마진이 신호였던 건(AUROC 0.94) 모델이 원래 잘하는 일(사진 분류)이어서다. 모델이 못하는 일에선 마진이 크게 틀린다.

남은 것: 채점 경로 자체는 빠르고 동작한다 (생성보다 빠름). 쓸 곳이 생기면 — 더 큰 모델로 같은 12개 상황을 새 프로브로 다시 재거나, 전술 선택은 LLM 없이 진행도 기반 톰슨 샘플링으로.

### 클라우드 판단 모델 — 같은 12 상황 (2026-09-22, `cloud_judge_probe.py`)
판정선은 실행 전에 고정: (1) 일치 ≥ 8/10 (2) 모호한 상황에서 신뢰도가 더 낮다 (Gemini·Gemma = 그리디와 온도 1 샘플 3개의 일치 수, Jev = 확률 1·2등 차)
(3) 그리디 p50 < 1000 ms (반사가 아니라 교전 단위 판단 자리라 로컬 300 ms 보다 느슨하게). Gemini 3.x 는 게이트웨이 무료 등급에서 403 이라 Gemini API 직접(`GEMINI_API_KEY`).

| 모델 | 일치 | 틀린 답을 가려내나 | 그리디 p50 | 1회 비용(대략) | 판정 |
|---|---|---|---|---|---|
| 로컬 Qwen3-4B (S3 채점) | 3/10 | ✗ — 12개 전부 bomb_stop | 122 ms | 0 | 탈락 |
| Gemini 2.5 Flash-Lite (게이트웨이) | 4/10 | ✗ — 적 없는데 fight 를 3/3 확신 | 677 ms | $0.00004 | 탈락 |
| Gemma 4 26B A4B (게이트웨이, 분당 5회) | 4/10 | – | 1094 ms | – | 탈락 |
| Jev | 7/10 | ✗ — 틀린 셋의 확률차 0.40~0.43 이 맞힌 것(0.12~0.77)보다 안 낮다 (AUROC ≈ 0.57) | 361 ms | $0.00002 | 하나 차로 탈락 |
| **Gemini 3.5 Flash-Lite** (직접) | **8/10** | ✗ — 틀린 둘(s07·s08)도 3/3, 모호한 둘도 3/3 | 750 ms | ≈ $0.00015 | (2) 탈락 |
| **Gemini 3.8 Flash** (직접) | **9/10** | ✗ — 12개 전부 3/3 | 2168 ms (생각 180~955 토큰) | ≈ $0.002 | (2)·(3) 탈락 |

읽는 법:
- **정확도는 모델 크기를 따라간다** — 4B 로컬 3 → Jev 7 → 3.5 Flash-Lite 8 → 3.8 Flash 9. 3.x Gemini 는 상태를 읽는다 (적 없음 → sprint, 붙음 → fight, 뒤에서 추격 → sprint, 3.8 은 위층 폭탄 → sprint 까지).
- **신뢰도 신호는 어느 모델에도 없다.** 샘플 3개는 거의 항상 그리디와 같고(온도 1 에서도), Jev 확률은 틀린 답에서 안 낮아진다.
  VersionSandbox 의 "그리디 대비 불일치" 가 사진 분류에서 신호였던 것과 다르다 — 게이트(모르면 규칙으로)를 걸 근거가 없다.
- 3.8 Flash 의 첫 실행은 무효였다 — `maxOutputTokens` 256 을 생각('minimal' 인데도 123~248 토큰)이 다 먹어 답이 잘렸다. 한도 4096 으로 다시 잰 것이 위 숫자.
- 12 상황의 기대 답은 사람이 원칙에서 정한 것이다. s07(셋이 5~9 m → bomb_stop 기대)은 fight 도 4~9 m 에서 폭탄을 던지므로 경계에 가깝다.

결론(현재): "모르면 규칙으로" 식의 게이트형 판단기로는 쓰지 않는다. 쓴다면 **톰슨 샘플링의 팔 하나**로 — "교전마다 3.5 Flash-Lite 가 전술을 고른다" 를
고정 전술 넷과 같은 줄에 세워 결과(성공·진행도)로 비교한다. 그러면 신뢰도 신호가 없어도 되고, 틀린 판단의 값은 성적이 치른다.
